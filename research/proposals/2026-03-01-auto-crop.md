## 🔬 Researcher: Auto-Crop Feature (16:9 to 9:16)

### 🎯 Executive Summary
Propose adding an "Auto-Crop" feature to the `ffmpeg-service` that automatically converts standard 16:9 videos into 9:16 vertical format. This enhancement streamlines the workflow for content creators targeting vertical platforms like TikTok, Instagram Reels, and YouTube Shorts.

### 💡 Problem Statement
**Current situation:**
- The application generates highlights and can cut video clips, but it outputs them in their original aspect ratio (usually 16:9).
- Users who want to post these clips to vertical platforms (TikTok, Reels, Shorts) have to manually crop the videos using external editing software.

**User impact:**
- High friction in the content creation pipeline.
- Users spend extra time on manual editing tasks outside of AudioHighlights.

**Example scenario:**
- A user uploads a podcast episode recorded in 16:9 landscape format.
- AudioHighlights identifies a great 60-second viral clip and exports the video.
- To post it on TikTok, the user must open Premiere Pro or CapCut just to change the aspect ratio to 9:16.

### 🚀 Proposed Solution
**What:**
Introduce an Auto-Crop functionality that automatically converts 16:9 videos to 9:16.

**How it works:**
- Add a new endpoint or an option in the existing `cut-video` and `concat-segments` endpoints within `ffmpeg-service`.
- Use FFmpeg's video filter `-vf 'crop=ih*9/16:ih'` to center-crop the video to a 9:16 aspect ratio.
- Provide a toggle in the frontend `ConfigPanel` to enable or disable "Optimize for Vertical Platforms (Auto-Crop)".

**Why this approach:**
- **Zero Additional Cost:** Leverages the existing FFmpeg infrastructure.
- **Fast:** Center cropping is computationally inexpensive compared to complex reframing.
- **Immediate Value:** Solves a major pain point for the primary use case of the app (creating clips for social media).

### 📊 Research Findings

**Technology Analysis:**
- **Library/Framework:** FFmpeg `crop` filter.
- **Maturity:** Highly stable and widely used.
- **Implementation Effort:** Low. It requires adding a simple filter string to the existing FFmpeg arguments.

**Competitive Analysis:**
- Many modern clipping tools (e.g., Opus Clip, Riverside) offer auto-reframing. While advanced tools use AI to track faces, a simple center crop covers a large percentage of typical podcast setups (where the speaker is centered).

### 🧪 Proof of Concept

**Implementation:**
The POC (`research/pocs/auto-crop-poc.js`) successfully demonstrates generating a dummy 16:9 video and cropping it to 9:16 using FFmpeg.

```javascript
// From research/pocs/auto-crop-poc.js
function autoCropVideo(inputFile, outputFile) {
    const args = [
        '-y',
        '-i', inputFile,
        '-vf', 'crop=ih*9/16:ih', // Center crop to 9:16
        '-c:a', 'copy',
        outputFile
    ];
    // ...
}
```

**Performance:**
- **Before:** Manual export to external software, setup, re-render (minutes per clip).
- **After:** Automatic processing during the clip generation phase (seconds).

### 📈 Value Proposition

**Benefits:**
- ✅ **Seamless Workflow:** Users can post directly from AudioHighlights to vertical platforms.
- ✅ **Time Saving:** Eliminates the need for secondary video editing tools.
- ✅ **Higher Engagement:** Vertical videos perform significantly better on mobile-first platforms.

**User stories:**
- As a **Content Creator**, I can **export my highlights directly in 9:16 format** so that **I can post them to TikTok and Instagram Reels without extra editing.**

### ⚖️ Trade-offs

**Pros:**
- ✅ Very easy to implement.
- ✅ High user value.
- ✅ Fast processing.

**Cons:**
- ❌ **Center Crop Limitation:** It blindly crops the center. If the speaker is off-center, they might be cropped out. (Future enhancement: AI face tracking).
- ❌ **Re-encoding Required:** Unlike stream copying (`-c copy`), applying a video filter requires re-encoding the video stream, which adds processing time and consumes more server resources.

**Alternatives considered:**
| Alternative | Pros | Cons | Decision |
|-------------|------|------|----------|
| AI Face Tracking Crop | Perfect framing | High compute cost, complex | Defer for V2 |
| Padding (Pillarbox) | No content lost | Looks bad on vertical platforms | Not chosen |

### 🛠️ Implementation Plan

**Phase 1: Service Update** (estimated: 1 day)
- [ ] Add `cropToVertical` boolean parameter to `ffmpeg-service` endpoints.
- [ ] Modify FFmpeg spawn arguments to include `-vf 'crop=ih*9/16:ih'` when requested (requires removing `-c copy` for video and using a fast encoder like `libx264`).

**Phase 2: Frontend Integration** (estimated: 1 day)
- [ ] Add "Auto-Crop to Vertical" switch in `ConfigPanel`.
- [ ] Pass the parameter to the API calls in `useFFmpeg`.

**Total estimated effort:** 2 developer-days

**Dependencies:**
- None (uses existing FFmpeg setup).

**Risks:**
- ⚠️ **Processing Overhead:** Re-encoding video is slower than stream copying.
  - *Mitigation:* Use `-preset ultrafast` or `-preset veryfast` in FFmpeg arguments.
